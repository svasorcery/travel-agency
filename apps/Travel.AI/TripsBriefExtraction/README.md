# Trips brief extraction (source only)

The independent `TripsBrief` configuration section is startup-bound. `Enabled`, `ExecutionAuthorized`, and `PrivateTextProcessingAuthorized` default to false; processor/model, tariff and both spend allowances default to unset/zero. The current lazy SDK adapter supports only processor `anthropic`. It cannot label an Anthropic request as a local/different processor. No model/revision, processor terms, key or execution authorization is selected by this source change.

`Model` must equal the explicitly verified `PricingModel`; both positive per-million token prices and explicit `MaxRequestCostUsd` / `MaxHourlyCostUsd` are required. Allowances must be at most USD0.03/request and USD0.30/rolling hour and the hour allowance must cover one request. These are per-process reservations, not a provider invoice or fleet budget. Unknown usage/model/cost or failed accounting retains the complete reservation for the rolling hour. Only committed known accounting releases unused money. Before any separately authorized real pilot, use exactly one M3-enabled responder; restarts cannot establish a reset-safe global budget.

The policy identifier is SHA256 of the canonical JSON array `[processorId, exactModel, "trips-brief-ru-v1"]`, containing public configuration only. Host and AI compare the request identifier with their own configuration before forwarding/dispatch; AI checks again after predispatch storage. This is never a private-text hash.

`Program` excludes the feature from Production even when configured on. It registers the Core NATS subject `travel.ai.trips_brief` and stable queue group `travel.ai.trips_brief.workers` only when enabled outside Production. The existing initialization gate delays Wolverine startup until the checked-in AI schema initialization succeeds. The message-specific discard policy adds no retries/durable inbox/outbox, JetStream, deadletter payload or replay. Actual composed Host/NATS privacy acceptance is a separate required source check. Flights NL-search and fare-summary clients/listeners retain their registrations.

The keyed `IChatClient` key is `trips-brief`, separate from the default Flights client. Resolving its wrapper creates no SDK client/connection or key access; the lazy inner client is created only at an authorized admitted dispatch. SDK `MaxRetries=0`, one nonstreaming response and no model tools are used. Tests replace only this keyed client.

Input is at most1000 valid Unicode scalars /4096 UTF-8 bytes, with LF the only permitted control. A conservative full-envelope byte bound (system prompt, JSON schema, payload including reference data, model/options and framing reserve) must fit4096 input tokens; oversized text is refused without trimming. Output is at most1024 tokens and16KiB, parsed with depth8 and exact members/types/states/allowed values, bounded evidence/alternatives/issues and UTF-16 boundary checks. The Trips Application independently verifies meaning against finite source lexicons and date rules; parser acceptance alone does not establish semantic recall or model quality.

One active operation and at most6 starts/minute, without a queue. Handler work is bounded to4500ms and the propagated absolute Host deadline; inference is bounded to3500ms with time reserved for accounting. At least500ms must remain before admission and again after predispatch storage. A committed `Admitted` ledger row has nullable unknown usage/cost before any provider request. Expected outcomes are `Disabled`, `ModelUnavailable`, `ProcessingPolicyChanged`, `InputUnavailable`, `Busy`, `BudgetExceeded`, `DeadlineExceeded`, `InferenceFailed`, `Refused`, `InvalidOutput`, `AccountingUnavailable`, `Ready`. Unknown/mismatched returned model identity is never priced with the requested tariff, echoed as an arbitrary model string or accepted as a candidate. Missing usage is accounting-unavailable. Valid usage is recorded even for invalid output.

SDK/database cancellation is best effort. Bounded observers return controlled outcomes, discard late candidates and retain the active lease until every noncooperative SDK/accounting task settles. Accounting tasks own their own async scope/context. No automatic follow-up call or accounting retry occurs. A dependency can retain its own prompt until settlement; there is no physical RAM erasure or ten-minute dependency-retention claim.

The prompt, text, excerpts, candidate, provider payload/exception and private hashes are excluded from application logs/traces/storage. The extractor catches provider/parser/storage exceptions without logging/retaining their payloads. Accounting receives random attempt identity, configured public model, controlled outcome and nullable numeric usage/cost only. No owner/trip identity is stored. Provider HTTP payload logging/function invocation/response caching is not enabled. The shared request/field/result `ToString` implementations redact content. Do not enable SDK/bus/HTTP body recording for this route.

Manual M1 editing/saving and existing itinerary generation do not depend on this feature. A missing/unavailable M3 responder uses the manual form. Rollback changes startup flags and restarts the authorized target; editing a file is not instantaneous revocation, and already admitted provider work may settle and bill.

Fake model and newly disposable ledger tests prove mechanics only. Real model quality, observed cost/latency, processor/privacy acceptance, independent holdout, target provisioning and rollout remain not evaluated/pending. No credentials/billing/model request is needed for ordinary source tests.
