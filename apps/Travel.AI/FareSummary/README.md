# Bounded fare-summary candidate

This feature is off by default. No model or price is supplied by the source defaults. Enablement additionally requires an exact `Model` / `PricingModel` match, `PricingVerified=true`, and positive explicit input/output USD prices per million tokens. These values must be verified independently for the selected model before any separately authorized paid evaluation. NL-search configuration and pricing are independent.

The payload contains only primitive permitted fact IDs, section/kind/state, exact amount/currency/quantity, and zero-based scopes. Correlation, fingerprint, locale and deadline stay outside the model payload. The embedded `fare-summary-v1` prompt and strict JSON schema are included in the conservative UTF-8 byte admission estimate, with a 128-byte framing reserve; the feature rejects inputs above 2048 estimated tokens rather than truncating facts. This deliberately restrictive gate is not a provider tokenizer or billing guarantee. Captured payload tests and a separately authorized measured evaluation remain necessary.

Each process admits at most one active request and six admissions in a rolling minute, with no waiting queue. The SDK client has `MaxRetries=0`; the output cap is 512 tokens, the model call has an injected-clock limit of min(3.5 seconds, remaining absolute deadline), and known usage is accounted against the configured exact model price. Requests estimated above USD 0.10 are skipped. These are per-process and per-request guards: replicas, restarts and new ordinary quotes can increase account-wide spending.

Only exact permitted JSON section/group/ID shapes are accepted. Every supplied fact must occur once in its supplied section; grouped values must be semantically equal. Any omitted/duplicate/invented ID, extra field, duplicate JSON property, free text, non-text model content, oversize or wrong section returns a full fallback. The Flights formatter performs its own authoritative validation and supplies all displayed wording and mandatory notices.

Known usage is retained and written to the existing ledger even for a rejected plan. Missing usage returns `UsageUnknown` without a fabricated zero-cost ledger row. Missing/mismatched actual model metadata retains reported token counts but cannot fabricate actual cost. Ledger failure returns `AccountingUnavailable` and never repeats inference. A bounded `WaitAsync` also handles a client or ledger that ignores cancellation. The reply falls back at its deadline; the single-request lease remains held until the original task settles, so subsequent requests receive `Busy` without another inference. A never-settling dependency therefore keeps this process unavailable for the candidate until recovery; it is not silently retried. Cancellation cannot prove that a remote inference was unbilled, and missing usage/cost stays unknown. Fixed diagnostics contain status and token counts, never prompt/output/exception body/key. The Wolverine policy applies only to `FareSummaryRequested` and discards unexpected failures without handler retry; it does not change NL-search delivery defaults.

The source tests use fictional clients, intercepted fake HTTP, fake time and fake accounting. They do not prove a live model's quality, actual provider pricing, deployed streaming/topology, a global spend ceiling or exactly-once inference. Disposable transport/ledger acceptance belongs to the existing authorized CI topology; paid evaluation and deployment remain separate gates. Install the default-off consumer before enabling any producer; every consumer must join the exact stable fare-summary queue group.
