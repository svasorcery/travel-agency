# Trips M1 operations and HTTP contract

Trips is disabled unless `Trips:Enabled=true`. Disabled composition registers only the immutable feature value: it does not resolve a database, inspect keys, or discover private handlers. The prefix response policy runs before authentication and returns404 with `Cache-Control: no-store`. Enabled requests require authentication, an unambiguous GUID subject and trusted issuer. The destinations endpoint doubles as discovery:401 means authentication required,503 means enabled but unavailable.

Enabled operation needs the `travel` PostgreSQL connection, the checked-in Trips migration and an independently provisioned Trips key ring. `Trips:Protection:KeyRingPath` and `ActiveCertificatePath` are absolute paths; the active PFX must have a private key. Supply its password through existing secret configuration. `ReadCertificates` may retain previous PFX readers for recovery. Never copy a Support/Flights key ring. Application discriminator `Travel.Trips.Plans.v1` and purposes bind owner issuer/subject, trip ID, schema1 and revision. Runtime disables automatic key generation, never creates directories or keys, and fails closed on missing/revoked/expired usable keys. There is no Trips initialization/provisioning endpoint or migration initializer.

Readiness probes the protection ring, rejects pending Trips migrations, and runs a read-only schema query selecting every required column with `WHERE FALSE`. A missing schema/key returns unavailable; startup does not apply schema in any environment. Responses/errors are no-store; fixed RFC7807 codes never embed supplied title, notes or JSON. The module emits no private content, owner/trip metric labels, provider calls or model requests.

`POST /api/trips` accepts only `{title,brief}`. `PUT /api/trips/{id}` accepts only `{title,brief,days}`; each day is `{date,blocks}`, each block is `{blockId,title,note?,startTime?,endTime?,estimate?}`. Brief fields and the exact shared fictional POST/PUT/detail examples are in [design section4.1](../../openspec/changes/trips-m1-structured-planning/design.md#41-примеры-общего-http-контракта). Optional nullable values normalize to explicit nulls. IDs, money, dates and revision retain their defined string types; day and block array order is preserved. Server fields, duplicate JSON names and unknown nested fields are rejected. Dates are validated before Wolverine model binding to keep malformed private input out of framework exception responses.

POST returns201, `Location` and strong ETag; GET/PUT return200 with identical canonical saved detail bytes and ETag. DELETE returns204. PUT/DELETE require one strong `If-Match: "<positive Int64>"`; missing428, malformed400, stale412. Other outcomes include401/403, owner or unknown404, validation400, capacity/brief-change409 and readiness503. There are no automatic mutation retries or exactly-once promises. Check the current list/detail after an uncertain response before any explicit new action.

The payload is the complete canonical detail JSON without owner claims, encrypted before persistence. PostgreSQL stores only trusted owner/identity/revision/timestamps and protected payload. Owner guards precede decryption. Timestamp captures use UTC microsecond precision for PostgreSQL roundtrips. Before any commit the exact serializer measures the future complete detail including derived/server fields, maximum Int64 revision and maximum timestamp reserve. Incoming and complete decoded output each have an independent128KiB bound. Summary pages contain at most20 rows and no notes, blocks, interests or budget; any corrupt row fails the whole list rather than returning partial content. SQL projects an unavailable sentinel for ciphertext exceeding200000characters before materialization, so corrupt database values do not trigger unbounded application reads.

## Migration and rollback

`20261020143618_AddTripsPlanWorkspace` is additive: schema `trips`, `trip_plans` table, positive revision constraint and owner/updatedAt descending/tripId ascending index. Migration history is `trips.__ef_migrations_history`. [Reviewed idempotent SQL](Travel.Modules.Trips.Infrastructure/Persistence/Migrations/AddTripsPlanWorkspace.sql) touches only Trips-owned schema/table/index/history; no existing owner schema changes. SQL generation uses a fixed inert design-time connection and does not apply a database. Deployment must apply the migration through its separately authorized mechanism before enabling Trips. Create-table/index locks affect only the new Trips table; ordinary application startup does not migrate.

Recommended rollback is feature-off, preserving private plans and their keys for recovery. Migration `Down` drops the Trips table and loses plans: it is a separate destructive operation, never an automatic rollback. Restore requires the matching database backup plus retained Trips ring and certificate readers; do not claim that physical DELETE instantly erases backups.

## Verification boundaries

Lean source tests use real Wolverine routing/auth/model binding/canonical HTTP serialization with terminal in-memory store/protection fixtures. Separate protection tests use only temporary fictional test-owned certificates and rings. Relational tests marked `Category=Integration` use existing `IntegrationTestBase` with disposable `pgvector/pgvector:pg17`, apply only Trips migrations and create fictional rows. No test starts Host Program/AppHost, Keycloak, NATS, Redis, suppliers, models or an existing database. Source/lean/disposable acceptance does not establish deployed ingress, real identity configuration, target provisioning or rollout.

The emitted-diagnostics regression captures nonempty logger state/scopes and Activity tags/events through real Wolverine HTTP success/error paths, including an invalid opaque cursor. It uses the existing Host `Microsoft.AspNetCore=Warning` threshold: framework request-starting Information logs otherwise contain raw query strings. Keep that private-endpoint logging boundary when configuring a target; this source change does not replace the process-wide logging policy.
