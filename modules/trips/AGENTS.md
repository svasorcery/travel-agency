# Trips module

Trips M1 implements a private structured brief and editable calendar workspace. Its accepted capability contract is `openspec/specs/trip-plan-workspace/spec.md`; all 21 completed tasks, design, independent reviews and source/PR58/post-merge CI receipts are in `openspec/changes/archive/2026-10-20-trips-m1-structured-planning`. M1 is the foundation. M2 Moscow outdoor generation and fictional Rail intentions are source/demo and ordinary CI accepted, default-off/Test-only. Current contracts: [itinerary candidates](../../openspec/specs/trip-itinerary-candidates/spec.md) and [Rail intentions](../../openspec/specs/trip-rail-intentions/spec.md); [archive receipt](../../openspec/changes/archive/2026-10-22-trips-m2-moscow-itinerary/archive-verification.md) records26/27tasks, with6.3target/rollout still pending. Free-text brief extraction (M3), human route quality/calibration and enablement remain separate.

Core owns exact money, day/block invariants and non-destructive brief changes; Application owns owner guards, revision decisions and use cases. Infrastructure owns the Trips EF schema, atomic owner-capacity/CAS storage, protected canonical snapshots and read-only readiness. Api owns strict HTTP contracts and Composition. Host retains global builders and one endpoint map; Api code outside Composition must not import Infrastructure.

Trips is composed through its real Api facade and stays default-off. Disabled routes return404 before auth and resolve no Trips DB/protection services. Enabled private routes require a trusted owner principal; absent schema/protection fails closed. Ordinary startup never migrates schema or creates an empty key ring. Source migration and owned disposable PostgreSQL tests were explicitly authorized; existing/target database, keys and rollout remain separate. M1 is merged in PR58; documentary sync/archive does not authorise runtime enablement.

M1 makes no model, supplier, quote, booking, payment or cancellation call. User blocks and their estimates are intentions, not verified supplier facts. Unknown estimates stay separate from the known subtotal. Clients do not retry uncertain writes automatically and never retain private plans in browser storage or SSR output.

Local module behavior and operation configuration: [README](README.md). Test-only fictional HTTP/browser fixtures and disposable PostgreSQL evidence do not establish target readiness or itinerary/model quality. Preserve the exact requested fresh-dev ancestry when integrating alongside Rail.
