## OSS/demo and optional real access

Public source code and the explicitly selected fictional demo are complete uses of this module. A public deployment or a real Yandex key is not required for that scope. The [root OSS notes](../../README.md#ossdemo-use-and-your-own-provider-keys) describe the code license and provider boundary. Each deployment owner brings their own provider account/key and is responsible for their use of the API, including terms, quotas, permitted data use and attribution; this applies to forks and to the author's own demo.

- **Default:** `Rail:Enabled=false`, `Rail:Fictional=false`, empty `Rail:ApiKey`. Ordinary Host startup makes no Yandex request. The [key-free frontend demo](../../README.md#flights-frontend-demo-without-the-backend-stack) exposes `/rail` using authored data and a local banner; fictional transport is an explicit choice, never a fallback from real failure.
- **Credentials:** keep your own `Rail:ApiKey` in backend secret configuration, for example the `Rail__ApiKey` environment setting. Do not commit it, put it in the browser or URL, or share an author's key across clones. The client sends it in the outbound Authorization header. A key alone does not open the real source.
- **Before real use:** check the current [Yandex API terms](https://yandex.ru/legal/rasp_api/ru/) and [access instructions](https://yandex.ru/dev/rasp/doc/ru/concepts/access), the applicable tariff/remaining quota, and the intended site's eligibility. Historical500/day is not a configured allowance. The existing rights, budget and post-restart confirmation checks below remain required for each real deployment; obtaining a key or cloning code does not satisfy them.
- **Temporary cache:** the reference/catalogue bundle lives at most30minutes; complete search results at most300seconds, empty or damaged-ticket results at most30seconds, always bounded by reference expiry. Failed/limited searches are not cached. Data stays in bounded RAM with no browser persistence or real-response fixture archive. These are implementation bounds, not provider-approved TTLs; the operator checks their suitability against current terms.
- **Attribution:** real results require the safe official banner, supplied notice and active link described by the [copyright method](https://yandex.ru/dev/rasp/doc/ru/reference/query-copyright). The existing metadata/CSP/sandbox checks stay in place. Actual banner visibility must be checked for a chosen real deployment; the fictional banner proves only the demo flow.

Live access, registration, provider calls and deployment remain separate, explicitly chosen actions. Leaving those checks pending does not invalidate source/local/CI acceptance or require a live release to finish the OSS/demo project.

## Implemented contract

`GET /api/rail/stations?q=...` accepts3–80characters and returns at most20stations with temporary generation/evidence/attribution. `POST /api/rail/search` requires exactly `from`, `to` (each `{source:"yandex-rasp",code:"s..."}`), `catalogueGeneration`, strict `departureDate` and `transport:"train"|"suburban"|"all"`. No implicit date; product date budget is UTC today−1…today+30. Unknown/duplicate fields are400, body>8KiB413, process capacity429. Admitted execution returns200 `complete|limited|skipped|failed`. All responses are no-store. Expired/mixed generation is400 `Rail.StationSelection.Expired` before supplier search.

Application owns normalized ports/coordinators. Infrastructure owns wire/token/HTML/date/money mapping, typed HTTP and temporary cache. Host imports only Api.Composition, owns the one global Wolverine builder/endpoint map. Rail has no DB, migration, event/broker or cross-module import.

Every search response, even empty, must echo exact station identities/type/date. `thread.uid` is a source reference; identity includes source/mode/endpoints/instants. Optional `start_date` is source metadata, not a proved full-run start or key. Explicit offsets are preserved; unknown IANA/sourceUpdatedAt remain null. Original mode count precedes duplicate folding. One page50/mode, no retry/paging/enrichment.

Electronic-ticket marker and each fare/price are independent. Missing/null/incomplete price is not zero. Whole/cents must be mathematically integral before decimal conversion; RUB/USD/EUR only. Output is exact two-digit decimal string, including `9007199254740993.05`; browser never converts money through Number. Invalid optional components retain safe reasons and do not damage schedule completeness. Fare arrays stop at32with a separate ticket limitation. Seats and operational updates remain unknown/not-provided.

The cold reference bundle atomically combines safe banner/text/link metadata with streamed stations. No whole catalogue DOM/string/raw archive.32KiB token window,64MiB decoded/depth32/token16KiB,100000RF passenger stations,48MiB retained logical payload; parent metadata/candidates count toward staging. Known unrelated transports are discarded; unknown RF types produce limited coverage. No RF/zero usable stations or structural overflow is unavailable. Process admission has2whole autocomplete callers, one loader and no queue. Scans run under bundle ownership; old catalogue leases are not exported to search (only two station values).

Real access needs rights, current quota and restart confirmation. A persisted boolean never opens a new process: startup real admission is always closed. A fresh post-start options update must carry `BudgetConfirmedAt` after the injected-clock process start and not in the future, plus bounded verified remaining minute/day allowances and all confirmations. This source mechanism is not an account-wide quota proof or authorization to enable. All copyright/catalogue/search dispatches share rolling60s/24h nonrefundable debits;429never retries and Retry-After is not shortened.

Fictional mode explicitly selects terminal authored data; no fallback from real failures. In a separately authorized local configuration set Rail Enabled+Fictional; Production rejects Fictional. Source tests use terminal transports and lean TestServer, not actual Host/DB. UI `/rail` uses only component memory, separate field/search epochs and absolute expiry, no storage/history/SSR transfer cache. Safe240×130sandboxed attribution uses no-referrer; fictional frame is local and visibly labelled. Document frame policy is installed before browser bootstrap and auth; it adds only self, exact official banner path and the existing resolver's configured auth origin. Other/deployment CSP policies remain authoritative; meta cannot loosen them.

## M2 journey selection and route details (source, 2026-10-21)

The current unarchived change is [rail-m2-journey-selection-details](../../openspec/changes/rail-m2-journey-selection-details/proposal.md). Its [verification receipt](../../openspec/changes/rail-m2-journey-selection-details/verification.md) and [personal review](../../openspec/changes/rail-m2-journey-selection-details/personal-review.md) record accepted source/offline checks. Separately authorized actual Host/OpenAPI passed 3/3 and the fixed fictional mixed load/memory profile passed 6/6 cycles with 6000/6000 useful operations on 2026-10-22; see [runtime verification](../../openspec/changes/rail-m2-journey-selection-details/runtime-verification.md). CI and real-source/target gates remain pending. Historical M1 acceptance above remains bound to its original source.

`/rail` orders only the received immutable snapshot: departure instant (default), arrival instant or duration; equal values retain source order. Departure/arrival filters use each timestamp's own local clock: night [00:00,06:00), morning [06:00,12:00), afternoon [12:00,18:00), evening [18:00,24:00). Filters combine with AND. Carrier options come from the whole snapshot, with ordinal exact labels and separate unknown (null/blank); literal source label “Не указан” remains exact. Reset preserves sort; accepted new search resets all controls. Counts and empty-filter messages describe received rows, never a global ranking. No view action performs HTTP or refreshes fares/expiry.

`POST /api/rail/journey-details` is anonymous/no-store with strict8KiB JSON: `{search,expectedProfileEpoch,selection:{key,transport,departure,arrival}}`. Details require both existing source admission and **`Rail:JourneyDetailsEnabled=true`**, default false. Changing that option revokes the profile epoch. Explicit fictional configuration may opt in; existing M1 enablement does not opt in automatically. Real errors never fall back to fictional transport; Production rejects Fictional.

One operation rechecks exactly one fresh search mode, compares opaque key plus departure/arrival instants **and offsets**, then performs one bounded thread read. No matching by train number. Infrastructure extracts `thread.thread_method_link` only from the fresh response: exact supported HTTPS/schemeless Yandex hosts, `/v3.0/thread/`, exactly uid/date, strict one-time decoding and no other URL features. Only normalized UID and source lookup date survive; the URL is never followed. Lookup date may precede boarding date and is never guessed from boarding/start_date. Outbound host is always `api.rasp.yandex-net.ru`; query has no credentials or result_timezone.

Optional thread from/to echoes are station-code strings; departure_date/arrival_date compare calendar dates, while selected stop instants prove the occurrence. Required station identity and a unique boarding/alighting pair are mandatory, even with repeated stations. Scheduled times support whole seconds with Z/explicit offset, without guessed IANA zones or realtime. Stops retain independent reported/not-provided/unavailable times, dwell and platform. Terminal nulls and explicit zero dwell remain different; exact integer validation precedes numeric conversion, and Core rejects inconsistent chronology/dwell. Invalid optional dwell becomes unavailable while valid times survive.

Search and details share2 admitted operations/process, no queue. Each child (including full decoded body/parser) has5s, the operation8s; actual uncooperative children retain the permit until settlement. Shared quota is debited on each dispatch, without retry/refund. Thread:2MiB decoded,16KiB headers,depth32/token16KiB,2–200stops; public details512KiB. Ref128UTF-8bytes, UID100characters, labels1024UTF-8bytes. Details have no server cache and expire at min(full-body receive+60s,reference expiry); UI also applies the original search expiry and checks on open/apply/view resume. Fares and original snapshot dates remain untouched.

A usable fresh no-match conditionally removes only the captured old cache entry containing the selection. Concurrent replacement, other criteria/profiles and failures stay intact; the next manual search can obtain new rows. Recheck results do not populate search cache. One inline panel has separate cancellation/epoch, focus and expiry; sort preserves it, hidden selection/new criteria/close/attribution failure clear it. Attribution remains mounted, plain text and no-referrer. UID/keys/body/stations/dates/Authorization are excluded from emitted telemetry; only bounded safe outcome reasons are suitable for counters.

The local demo includes complete/partial/no-match/recheck-failed/route-failed/quota outcomes on authored data. It proves fictional contracts and browser lifecycle, not supplier compatibility. No Trips, inventory, purchase or passenger contract is introduced.
