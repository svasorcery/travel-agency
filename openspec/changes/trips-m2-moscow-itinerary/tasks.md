# Tasks

**Goal:** предложить и явно принять первый реальный прогулочный маршрут по Москве, затем отдельно добавить выбранное fictional Rail-намерение через существующий приватный M1 workspace; real Rail остаётся transient.

**Architecture:** deterministic Trips candidate, разрешённый versioned curated package, ephemeral preview, ordinary M1 PUT/CAS; нет нового persistence или AI runtime. Stack: текущие .NET/Angular/TypeScript/ErrorOr/TimeProvider.

**Spec:** [trip-itinerary-candidates](specs/trip-itinerary-candidates/spec.md) и [trip-rail-intentions](specs/trip-rail-intentions/spec.md). **Design:** [decisions/gates](design.md). 2026-10-21 пользователь согласовал план и разрешил source implementation для Москвы в новом worktree от свежего dev,изолированные source tests и independent audit/fixes;без push и включения. После исследования пользователь выбрал v2offlineOSM+модельные оценки с demo целью. Source/data-v2 adaptation выполняется по отмеченным ниже deliverables;D_demo механически проверяет реальные input/derived artifacts,а D_live/Q_live требуют своих фактических human подтверждений;существующие БД/ключи,Host/model/provider/deploy и stage/commit/merge этим разрешением не добавлены. Checkbox completion — deliverable+проверка, не факт получения разрешения.

**Global constraints:** preserve all M1 bounds/privacy/revision/no-retry semantics;1–3generation days vs1–14manual;0model/provider effects; exact money; one canonical corpus. No auto commit/push/migration steps. Implementation уже разрешена; этот refinement фиксирует новый consumer и review order, но не даёт publication/enablement authority.

**Review focus:** late candidate after dirty form/save/logout; valid client request but invalid produced fact references; correct fake IDs but no lawful real coverage; filled stops with unknown access/cost; competing CAS after staging. Owning tests:4.2,2.3/3.2,1.2/3.1,2.2/4.1,4.3 respectively.
