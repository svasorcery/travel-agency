# Design

## Context

[Ревизия](audit.md) фиксирует путь DTO → mapper → offer → quote events → HTTP/TS → экран и потерянные факты. Цель — в [proposal](proposal.md); поведение — в [spec](specs/flights-fare-rules-summary/spec.md). Сейчас нет подтверждённого источника полного текста правил, а отдельный публичный reader по aggregateId обошёл бы owner-boundary до hold.

## Goals / Non-Goals

**Goals:** точное объяснение ограниченных structured facts; независимая от AI работоспособность; связь с quote revision и сроком предложения; чтение сохранённых условий без PII/decrypt/supplier/LLM; проверяемый небольшой AI-кандидат.

**Non-Goals:** получение полного fare-rule text, обмен билета, создание cancellation quote, финансовая политика, расчёт возврата/FX, after-departure/no-show/involuntary policy, новая авторизация, durable AI workflow, conversation/RAG/tools/agent platform, повторная AI-генерация истории, законченный глобальный account-spend controller. Никакое выполнение этих решений в текущем planning turn не разрешено.

## Decisions

### D1. Варианты и минимальное решение

| Вариант | Польза | Стоимость/ограничение | Решение |
|---|---|---|---|
| A. Только нормализованные данные и шаблоны | Полная проверяемость; быстро; без AI-ключа; уже достаточно для двух условий | Смешанные области могут требовать несколько групп | Обязательная основа и постоянный fallback |
| B. AI группирует разрешённые утверждения, приложение формирует текст | Проверяемая гипотеза: более понятная организация исключений на сложном маршруте | Дополнительные задержка/стоимость; польза над A пока не доказана | Реализуемый ограниченный кандидат, выключен до отдельной оценки |
| C. Свободный пересказ полного текста / поиск по бренду | Теоретически больше подробностей | Источник текста не установлен; ложные правила и prompt injection; добавляет retrieval | Отклонён для этого среза |

Рекомендуется A+B с общей моделью фактов и одним formatter. Модель не нужна, чтобы отличить null от false или вывести сбор. Не заявлять, что ограниченный formatter является пересказом полного текста. Если оценка не покажет практической пользы B, оставить A и зафиксировать этот результат для M3-review; не усложнять runtime ради исторической метки «AI-фича№3».

### D2. Структурированные факты и области действия

Новый Core `FareRuleEvidence` — immutable provider-neutral value object, factory с ErrorOr. Wire DTO остаются в Infrastructure. Две отдельные root conditions для всего предложения/всех взрослых: `changeBeforeDeparture`, `refundBeforeDeparture`. Condition: `permission=Allowed|NotAllowed|Unknown`, `penalty=KnownMoney|Unknown`, `scope`, и фиксированный reason code для неизвестности/некорректности. Денежная пара KnownMoney допустима только при целиком валидных неотрицательных amount/currency. Missing allowed/null condition -> Unknown, а не запрет; known amount0 отличается от unknown. Amount сохраняется точно через существующие Money/decimal-string conventions, без округления через JS number.

Отдельно: массив slice change conditions для каждого из1–4 legs; brand по slice; настоящий fare basis и включённый checked/carry-on baggage по каждой паре adult–segment. Root не выводится через AND/OR отдельных slices. Refund root не разбивается по legs. Поле brand — label, не основание правил; uniform legacy FareBasisCode заполняется только реальным одинаковым кодом на всех применимых парах, иначе null. Cabin marketing не обобщается из первого сегмента в новое объяснение.

Baggage: explicit quantity0 — известный ноль; missing collection/type/invalid quantity — unknown. Пустой список сам по себе не доказывает нулевую норму в новом объяснении. Не использовать Max или Sum(empty) как источник. Нормализовать одинаковые новые included-baggage факты для fare explanation и ancillary display, сохраняя selected extras, их цену и исторический accepted purchase без переинтерпретации. Purchase/actual services не являются fare-rule evidence.

Границы данных: максимум64 сегмента предложения,9 взрослых,576 пар; текстовый бренд≤256 символов, code≤64, фиксированные enum/IDs, wire и normalized graph≤128KiB. Превышение/повреждение только fare evidence -> `Unavailable` для объяснения без выдуманных фактов; валидность обычного offer/party/booking проверяют существующие guards. Не добавлять новые ограничения на исторические itinerary constructors. Каждое отсутствующее поле хранит unknown, а не default0.

Infrastructure выделяет всю информационную fare-ветку того же полученного JSON через bounded tolerant reader до строгой десериализации этих optional значений: root/slice allowed/penalty, included baggage collection/type/quantity, optional brand/code/cabin marketing labels. Presence-aware quantity отличает explicit integer0 от omitted/null/wrong-type/overflow; неизвестный baggage type и неоднозначные duplicate entries не превращаются в подтверждённую норму. Некорректный label не становится кодом и не обрывает чтение остального offer. Reader сохраняет Unknown/Unavailable с фиксированным reason, не исправляет исходное значение и не делает повторный HTTP. Один и тот же путь применяется к search, RefreshOfferAsync и ancillary ReadCatalogAsync. Обязательные price/party/itinerary, available services и выбранные/фактические приобретаемые услуги сохраняют строгие guards: tolerant included allowance не разрешает покупку malformed service. Raw JSON fixtures отдельно проверяют все три пути, включая omitted/null/wrong-type/overflow quantity и malformed labels; никаких изменений обязательного supplier-контракта ради прохождения тестов.

Normalized facts несут schema1, provider source=offer, наблюдённое supplier-response время через TimeProvider, offer expiry и earliest departure instant из полного itinerary. Payment deadlines, quote expiry и «до вылета» — разные понятия; абсолютный fare deadline не создаётся из них. Полный текст, after-departure, no-show и involuntary сведения в v1 отмечены NotProvided. Даже известный нулевой penalty означает только указанный сбор; изменение может требовать разницу тарифа, а refund не доказывает возврат полной цены или зачисление.

### D3. Сохранённый снимок и идентичность

Добавить optional evidence в `BookableOffer`; optional `QuotedFareSnapshot` в оба события `OfferQuoted` и `OfferReQuoted`, текущий rich snapshot в aggregate. Snapshot связывает evidence с `OfferId`, `QuoteBinding.Revision`, числом взрослых и canonical source fingerprint. Application writer создаёт snapshot один раз из exact refreshed offer и новой binding до commit и сохраняет его вместе со schema/fingerprint version в том же quote event. Apply/replay копируют сохранённый snapshot: не вызывают текущий mapper/formatter, не берут новое время и не пересчитывают fingerprint по будущему алгоритму. Если replacement event не содержит полного frozen snapshot/RefreshedOffer/binding, текущий snapshot очищается в Unknown; старые источники не upcast автоматически. Исторические JSON constructor/Apply читают старые события без fresh-rule validation и без переписывания; старые события не получают выдуманный snapshot.

Mapper сопоставляет supplier passenger references строго по имеющейся party-модели; quote normalization переупорядочивает пары по current binding slots. Возвращаемые пользователю номера1–9 соответствуют этим slots, а не позиции произвольного supplier массива. Reference mapping остаётся на сервере. Snapshot fingerprint охватывает provider offer identity, маршрут с UTC instants/cabins, count, scope, permission, money, baggage/code/brand, observedAt и original offer expiry. Схема/locale/render version добавлены в presentation key. SHA256 — ключ согласованности, не authentication token и не permission.

`FareConditions` и старые bool-поля остаются readable legacy surface; новые readers не используют их для достоверного объяснения. False из старой модели неразличим с default false. Новый snapshot не меняет request fingerprints, cancellation/refund receipts, события HeldV1/V2/V3, consent hashes и финансовые eligibility decisions.

Search cache key/envelope -> v5 с explicit validation нового optional evidence и current capability inventory; v4 естественно истекает, без flush. Cache остаётся search hint; quote всегда использует обычный refresh. Dedup key явно сериализует только семантические fare facts, без observedAt, generated IDs, snapshot hash, prompt/model и render metadata. Rank policy остаётся price-first; не сливать разные подтверждённые условия.

### D4. HTTP/UI без нового reader и изменения auth

Существующий POST `/api/flights/orders/quote` возвращает добавочный `fareSummary` schema1: presentation binding, source observation/expiry, отдельный serverObservedAt ответа, `Current|Stale|Unavailable`, полный typed facts/details, компактные sections, warnings/missing information, `Deterministic|AiOrganized` и отдельный `aiStatus` reason enum. Никаких supplier DTO/raw output. Сначала ordinary quote commit, затем формирование необязательного AI-результата; quote success не зависит от AI. При conflict/failed quote commit AI не вызывается. У explanation нет отдельного endpoint, mutation command или supplier-read; открытие disclosure ничего не отправляет.

История: добавить optional `quotedFareSummary` в существующий GET `/api/flights/orders/{id}/creation`, после нынешнего owner/consistency guard. Читать retained rich snapshot без PII columns/decrypt. Это всегда «Условия при расчёте предложения», provenance Historical/Unavailable, не текущие условия созданного заказа. Не генерировать AI на GET и не ставить события/сообщения в outbox. Ownerless pre-hold история через этот reader по-прежнему недоступна; публичное объяснение живёт только в текущем quote-response. SSE/fallback могут перечитать историю, но не генерируют AI и не обновляют fare policy из webhook.

Current presentation допустима только для exact displayed offer/revision/fingerprint, до original offer expiry и earliest departure instant. Любой новый quote, выбор другого предложения, logout/identity epoch, navigation или expiry снимает статус актуальности и инвалидирует callbacks. Исторический результат можно оставить только с явной меткой; ни server timestamp, ни client elapsed time не продлевает deadline. HeldUntil не заменяет original offer expiry. Browser сохраняет данные только в памяти.

После ожидания AI сервер повторно проверяет часы и свежими source metadata убеждается, что сохранённая quote revision/fingerprint всё ещё текущая и creation не началась. Этот read не возвращает новые private данные и не вызывает provider/AI. Истечение во время inference -> Stale/Expired; новая revision или создание -> Stale/Superseded; freshness read failure/нехватка remaining budget -> Stale/FreshnessUnknown. Поздний AI plan не помечается действующим; можно вернуть прежние deterministic facts только с этой явной меткой. Ordinary quote success/financial guards не заменяются новым business отказом и не вызывают повторный quote. Это проверка актуальности на момент ответа, а не обещание непрерывной свежести между вкладками; server hold guards остаются окончательными.

UI показывает компактно обмен/возврат до вылета, имеющиеся сборы и пробелы; root и leg exceptions разделены. Багаж/code/brand — раскрываемые детали с пассажирами/сегментами и проверенной группировкой одинаковых фактов. Для4legs/9adults текст не превращается в576 одинаковых строк: exact equal facts можно группировать, различия сохраняются в доступных деталях. Plain Angular text, без HTML/Markdown исполнения. Mandatory notices про полноту, финансовую независимость и историчность модель удалить не может. Никакой accept-summary checkbox и изменения кнопок финансовых действий.

Правила купленных/выбранных мест и дополнительного багажа отдельно NotProvided, если нет собственного подтверждённого источника. Root fare condition и base-fare penalty не доказывают возврат или изменение ancillary services, даже если final quote включает их цену. UI не распространяет такую условную сумму на extras; actual cancellation quote остаётся отдельным whole-order финансовым источником. Mandatory notice об этой границе включается, когда quote содержит selected services.

### D5. Минимальный AI-кандидат и доверие

Travel.AI принимает новый shared leaf v1 message pair: identities `travel.ai.fare-summary.requested` / `travel.ai.fare-summary.planned`, subject `travel.ai.fare_summary`, stable queue group `travel.ai.fare_summary.workers`. Host владеет publish route через прежнюю module facade; Travel.AI — listener. NL-search v1 не меняется. Request: correlation, fingerprint, promptVersion, locale=ru, deadline и bounded catalog разрешённых fact IDs/scopes/typed values. Response: те же correlation/fingerprint/versions, `sections[{kind, groups[{factIds}]}]`, usage/model metadata или typed unavailable reason. Обычный Core NATS request/reply, без durable replay, response cache, нового брокера и mirrored CLR contracts.

Модель не пишет свободные утверждения. Она выбирает группировку/порядок проверяемых fact IDs в заданные секции. Formatter владеет формулировками и вставляет деньги/валюты/пассажирские номера/ограничения из серверного snapshot. Validation требует: exact identity, известные IDs, каждый обязательный факт ровно один раз, валидный section kind, размер≤16KiB, не более64 groups, объединение только семантически равных утверждений с exact scope union. Свободный text, дополнительные поля, изменённые деньги/сроки, выдуманный ID, пропущенное ограничение или неверная группа -> полный deterministic fallback; не ремонтировать ответ вторым model call.

Модель получает только allowlisted facts. Не передавать aggregate/owner/slot/supplier IDs, names/DOB/documents/contacts, saved profiles, protected snapshots, payment refs, auth headers или secret/options objects. Raw supplier text, бренд/code/URL не передаются модели: они безопасно отображаются отдельно. Любой supplier label рассматривается как данные, не prompt instruction. System prompt неизменяемый и версионированный; никаких tool/function calls, retrieval, conversation history или действий по ответу модели. Ошибки/логи фиксированы: reason/latency/usage/version без prompt, output и supplier/user body.

AI выключен по умолчанию; при будущем разрешённом включении используется только в текущем authenticated ordinary quote, с явным `explanationMode=organized` optional request field. Anonymous/legacy quote всегда получает deterministic результат; чтение готового объяснения никогда не запрашивает такой режим. UI выбирает режим перед обычным расчётом, не делает новый quote ради открытия объяснения. Не добавлять auth policy или выдавать режим за business permission. Попытка AI — одна на успешный quote request; reload/history/SSE/timeout не повторяют её. Повтор обычного quote — новая revision и отдельная явная операция пользователя, без exactly-once/budget-dedup обещаний.

Запрет автоматического повторения действует на всех уровнях: caller, Wolverine handler/delivery policy и SDK. Политика применяется только к новым fare-summary messages, не меняет NL-search или process-wide retries. Любая ошибка после возможного inference, включая accounting/result delivery, даёт fallback/error diagnostics, а не повторное выполнение handler с model call. Публикация/доставка не объявляется exactly-once; duplicate fault injection в existing transport CI отдельно проверяет отсутствие framework-induced inference retry после ошибки.

### D6. Время, стоимость и ошибки

Feature-specific IChatClient поверх существующего Anthropic SDK с `MaxRetries=0`, MaxOutputTokens512, без дополнительного retry middleware. Не менять существующий NL-search client/model. До вызова: enablement/auth/mode, nonempty useful fact set, payload≤16KiB, conservative estimated input≤2048 tokens включая system/schema overhead, valid configured model+price metadata, upper estimated cost≤USD0.10. Если estimator не может дать консервативный предел — skip; не посылать сырой длинный граф. Вся богатая evidence остаётся у formatter; model catalog заранее объединяет идентичные факты. При большом разнообразии, не помещающемся в пределы, используем A, не обрезаем существенные сведения.

Дополнительные пределы —1 одновременно исполняемый запрос и6 admissions/minute на AI-процесс, без очереди ожидания. Это process/per-request guard, не global/monthly account ceiling: scale-out/restart/повторные обычные quotes увеличивают совокупную стоимость. Для настоящего глобального лимита нужна отдельная задача; default-off не подменять обещанием экономического hard cap.

Предлагаемый budget Flights для всей optional стадии, включая финальную проверку freshness: min(4s, остаток до12s от начала handler, остаток до original offer expiry, остаток до earliest departure); это выбранный предел, не измеренный SLA. Если времени после refresh/commit нет — сразу fallback. Не менять provider timeouts/retry/financial guards или текущий15sclient timeout. AI получает absolute deadline и проверяет его до model dispatch; собственный linked cancellation ограничен ещё3.5s и remaining time. Поздний reply не применяется. Отмена HTTP завершается штатно, не конвертируется в business отказ; background financial activity отсутствует. Deadline не доказывает, что удалённый inference не был тарифицирован; автоматического повторения нет. Отсутствие времени на финальный source read не может превратить непроверенный snapshot в Current.

Ledger использует existing schema, feature `flights.fare_summary`, отдельную message identity и server correlation. Полученный usage записывается даже при rejected output; отсутствие usage не становится нулевой фактической стоимостью: фиксируется `UsageUnknown` через typed diagnostics/metrics, без ложной ledger row. Ledger write failure не меняет готовые fare facts; возвращается deterministic и `AccountingUnavailable`, повторного model call нет. Метрики отделяют attempts/skipped/unsupported/inference-error/invalid-output/unknown-usage/accounting-error; модели с непроверенной ценой не допускаются. Hardcoded NL цены не объявляются текущим тарифом нового model. Paid run отдельно подтверждает provider usage и pricing перед включением.

### D7. План по слоям и доказательства качества

| Область | Изменения после отдельного apply-разрешения | Проверка |
|---|---|---|
| Core | Evidence/snapshot factories, optional offer/event facts, safe Apply/invalidation | Tri-state, source scopes, exact money, old JSON/events, same-price revision |
| Application | Bind/formatter/validator, quote optional stage, creation-history reader result, stable dedup | Нет новых финансовых операций, zero AI на failed commit/GET, deterministic fallback |
| Infrastructure | Duffel DTO/maps, consistent included baggage, cachev5 | Fictional raw JSON omitted/null/false/true, malformed fee/currency, differing adults/legs |
| Api + Host facade | Additive quote/creation DTOs, optional mode, route contribution | Existing auth/no-store, ownerless/foreign concealment, OpenAPI/old DTOs; Host глобальные owners сохранены |
| Leaf + Travel.AI | Versioned messages, extractor, prompt, bounded feature client/handler, ledger reuse | Shapes/identities/architecture; fake IChatClient; existing disposable NATS/ledger CI topology |
| TS/Angular/demo | Strict new decoder, quote disclosure/details, historical panel, epoch/expiry handling | Fakeclock/pure formatter/client/UI + isolated fictional Node/Playwright |

Контрольная fictional выборка:48 случаев с распределением12 missing/legacy,12 permissions/fees,12mixed scope/baggage/party,12injection/stale/error/budget; не менее12 adversarial outputs. Данные фиксируются до настройки prompt. Отдельная holdout-часть16 случаев не используется для prompt tuning; обе части включают9adults/4legs и нулевые/разные валюты. Gate offline:100% money/scope/unknown correctness,100% mandatory fact coverage,100% unsafe-output rejection и отсутствие business mutations. Это доказывает приложение на заданных outputs, не качество живой модели.

Primary category распределяет48case IDs, дополнительные tags могут пересекаться. До tuning составляется manifest32tuning/16holdout; holdout включает заранее выбранные≥12AI-eligible mixed cases для сравнения A/B и≥4ineligible cases ожидаемого отказа/отсутствия данных. Eligibility определяется из source/input/config до ответов модели, а не по успешности output. Offline проверка применяет все48cases; модель вызывается только на допущенной подвыборке. Нельзя после run исключать неудачные eligible случаи, добирать понравившиеся примеры или переносить holdout в tuning. Captured-payload fake test показывает, какие репрезентативные inputs реально помещаются в bounds с system/schema overhead; отсутствие≥12допустимых mixed holdout cases оставляет B выключенным.

Отдельно разрешаемая real-model оценка использует тот же extractor и fictional holdout, фиксирует model/prompt/render/config, usage/cost, latency, fallback и rubrics. Требования до включения B:0 отображённых неподтверждённых утверждений;≥95% действительно валидных AiOrganized plans среди заранее eligible holdout cases; p95 всей optional latency≤4s; фактическая request cost≤USD0.10 на измеренной выборке. Timeout, invalid output, skipped eligible attempt и deterministic fallback входят в знаменатель, но не в successful AI numerator. Ineligible cases проверяют zero dispatch/честный отказ и не выдаются за model pass. Два независимых русскоязычных читателя вслепую сравнивают A/B на заранее выбранных≥12eligible mixed holdout случаях: B должен выиграть хотя бы в8, проиграть не более чем в1, без потери обязательных фактов. Fallback показывает A и не считается выигрышем B. Провал -> A остаётся, B выключен. Нет LLM-as-judge или заявлений об экономии на реальном потоке. Маленькая выборка и human rubric имеют явную ограниченность.

Обязательная source acceptance — существующие CI lanes, в том числе durable stream/cache/owner/transport/ledger tests и PR E2E. Отдельная оценка модели не заменяет CI. Live acceptance — отдельно разрешённая проверка запущенного окружения и rollout compatibility; provider/payment действия отсутствуют даже в этом probe. Детальные команды/ожидаемые доказательства — в tasks.md; planning receipt — в verification.md.

## Risks / Trade-offs

- Rich contract больше двух flags → ограниченный graph, grouping и strict decoder; источник отдельно от rendered text.
- Старые bool уже потеряли unknown → историческая Unavailable, без upcast по бренду/старому false.
- Older UI продолжает старую двузначную трактовку → новый decoder/UI выкатываются раньше enablement; совместимость формата не означает достоверность старого интерфейса. Активное объяснение гарантируется только новым reader.
- AI selection может быть бесполезнее A → количественный/human comparison gate и default-off; отказ от AI — допустимый честный результат.
- Timeout/ledger uniqueness не обеспечивают inference exactly-once → one attempt, no replay; cost ambiguity видна, глобальные гарантии не заявляются.
- Legacy re-quote без refreshed graph → очищать текущую evidence, не переиспользовать старую.
- Source-only чтение через creation может иметь EF lag рядом → existing version guards и owner source остаются независимыми; summary не включает canConfirm/canCancel.

## Migration Plan

EF/Marten schema/migration не требуется: только additive optional event/DTO fields и новая cache namespace. После отдельного разрешения: сначала новые tolerant readers + snapshot tests, затем emitters/cachev5 и UI; AI transport consumer может быть установлен default-off раньше producers. Старые данные читаются, источники не backfill. Summary fallback отсутствующего поля обязателен для mixed-version rollout. Новые AI identities не пересекаются с NL-search; никаких group-less listeners.

Rollback выключает organized mode и возвращает A; не удаляет сохранённые rich facts и не меняет financial history. Старый бинарный reader может игнорировать optional поля, но его двузначный UI нельзя объявлять достоверным fare-summary. Проверить реальные старые JSON fixtures и unknown-field behavior в обязательном CI; live deploy и контроль старых browser assets отдельно согласуются. Sync/archive, ADR/current-state/docs публикация — последующие отдельные разрешения, не часть текущего planning результата.
