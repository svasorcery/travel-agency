# Trips M1: структурированные пожелания и редактируемый план

## Why

Пользователю нужен маршрут, который система предлагает по пожеланиям и который затем можно редактировать. Trips пока содержит только каркас; сначала нужны независимая от AI модель пожеланий, приватный сохраняемый план и проверяемые правила редактирования, чтобы генерация не стала единственным владельцем пользовательских данных.

## What Changes

- M1: структурированная форма для одной поездки в один выбранный город, календарь дней, ручные блоки плана, сохранение/reload, список своих поездок и удаление. Календарь с пустыми днями обозначается как основа плана, а не сгенерированный маршрут.
- Зафиксировать границу: Trips владеет пожеланиями и принятыми версиями плана; Travel.AI впоследствии предлагает кандидата; пользователь решает, применить ли изменения. В M1 модель и поставщики не вызываются.
- Спроектировать следующий M2: та же форма → предложенный маршрут → редактирование. Проверенные исходные сведения, объяснение ограничений, защита пользовательских правок и отдельная оценка качества обязательны. M2 требует нового change; его поведение здесь не объявляется реализованным или полностью специфицированным.
- Оставить M3 для свободного текста, заполняющего тот же контракт пожеланий, и последующих уточнений. Общая агентная платформа развивается по потребностям этих потребителей.
- Изолировать M1 от незавершённого Rail: без новых импортов соседних модулей, их внутренних DTO и хранения результатов их поиска. В последующих этапах каждый реальный потребитель получает конкретный опубликованный контракт.
- Приведённые численные пределы, API и технические решения — предложения автора для утверждения; согласованы сценарий и порядок этапов, а не эти детали.

## Capabilities

### New Capabilities

- `trip-plan-workspace`: owner-private structured trip brief, bounded day/block editing, exact optional user estimates, revision-checked persistence and an honest non-generating M1 UI.

### Modified Capabilities

Нет. Контракты Flights, Hotels, Rail и Support не изменяются.

## Impact

Предполагаемые будущие изменения: четыре слоя `modules/trips`, существующие Trips test projects, Angular `/trips`, shared TS client, Trips Api.Composition, точечное включение в Host/inventory/ordinary CI и собственная EF schema `trips`. Source migration требует отдельного разрешения; применение схемы, ключи и target enablement не следуют из планирования.

Новые runtime-пакеты, Redis, брокерные workflows, MAF/Semantic Kernel, supplier calls, paid/model calls и общий SDK для гипотетических потребителей не нужны M1. В текущем change создаются только planning artifacts и результаты проверки. Детальные задачи M1 составляются после независимого аудита дизайна; реализация требует следующего поручения.
