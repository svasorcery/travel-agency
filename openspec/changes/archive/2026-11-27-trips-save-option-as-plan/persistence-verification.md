# Миграция, конкурентная запись и срок талона

Локальная проверка 27 ноября 2026 года использовала PostgreSQL 17 в одноразовых контейнерах `pgvector/pgvector:pg17` и вымышленные учётные записи. Предыдущий Host собран из `e589d8624c80f499a8f9587623288652cc23372f`. Оба Host запускали настоящий `Program.cs` в окружении Testing с одним временным кольцом Trips. Только проверочная оболочка передавала процессам адрес контейнера и ключи. Для этой проверки использовался тестовый principal.

## Матрица схемы

Из корня репозитория запустить [verify-schema-matrix.ps1](verify-schema-matrix.ps1) в PowerShell 7. Скрипт извлекает базовый коммит в новый временный каталог, компилирует одну проверочную оболочку с каждым Host и запускает её с новым изолированным PostgreSQL. Прежний Host остаётся запущенным в отдельном процессе через расширение и откат схемы. Оболочка сверяет оба сохранённых SQL-файла с SQL актуального EF-мигратора до выполнения.

| Условие | Наблюдение |
| --- | --- |
| Прежний Host и прежняя схема | POST ручного плана 201, GET 200 с тем же ID и названием. |
| Новый Host, прежняя схема, сохранение выключено | Приватный запрос вернул 503. История EF и физическое отсутствие нового столбца и таблицы сохранились. |
| Расширение при работающем прежнем Host | Старый план открылся. Прежний Host создал и прочитал второй. У обоих ревизия 1 и NULL в историческом столбце. |
| Новый Host, расширенная схема, сохранение выключено | Оба прежних ID открылись. POST третьего ручного плана вернул 201, GET 200. Все три записи сохранили NULL и ревизию 1. POST сохранения выбора вернул 404. |
| Новая запись включена после этих проверок | Реальный preview выдал выбор, POST сохранения вернул 201, исторический GET вернул 200 и объект снимка. |
| Выключена запись, проверяется Down | При живом снимке без квитанции и отдельно при квитанции без плана PostgreSQL отказал с P0001. При недоступной таблице квитанций он отказал с 42P01. Во всех трёх случаях сохранилась запись EF о расширенной схеме. |
| Доказан ноль исторических данных | Down вернул прежнюю схему с тремя ручными планами. Прежний Host прочитал исходный и созданный новым Host планы, создал и открыл ещё один. |

Матрица завершилась с кодом 0. Миграция `20261127164744_AddSavedOptions` добавляет nullable text без переписывания прежних строк, первичный ключ `trip_id` и индекс по `expires_at`. Квитанции не имеют каскада от плана. При Down транзакция берёт `ACCESS EXCLUSIVE` на обе таблицы до проверки данных и удерживает блокировки до завершения DDL. Проверка требует отсутствия всех квитанций, включая ещё не очищенные истёкшие. Применение SQL к целевой базе требует отдельного разрешения и согласованного окна.

## Гонки за сотое место

Для воспроизведения запустите тесты из корня репозитория.

```powershell
dotnet test tests/trips/Travel.Modules.Trips.Tests.Integration -m:1 --filter "FullyQualifiedName~SavedOptionPersistenceTests"
```

Каждый опыт начинает с 99 ручных строк одного владельца. Две независимые HTTP-операции используют настоящий EF store, защиту и PostgreSQL. Interceptor останавливает первую транзакцию после записи перед commit. Третье соединение подтверждает реальное ожидание advisory lock через `pg_locks` и `pg_blocking_pids`. В этот момент оно видит 99 строк и ноль квитанций, а независимый владелец получает 201 через свой HTTP-запрос.

| Держатель | Ожидающий | Ответы | Повтор выбора | Снимки / квитанции исходного владельца |
| --- | --- | --- | --- | --- |
| Выбор S | Тот же S | 201 / 200 | 200 | 1 / 1 |
| Ручной | S | 201 / 409 CapacityExceeded | 409 CapacityExceeded | 0 / 0 |
| S | Ручной | 201 / 409 CapacityExceeded | 200 | 1 / 1 |
| S с отказом до commit | Ручной | 503 / 201 | 409 CapacityExceeded | 0 / 0 |
| S с отказом до commit | S | 503 / 201 | 200 | 1 / 1 |

В каждом опыте наблюдатель проверяет, что остались исходные 99 ID и добавился только ID победителя. У всех 100 планов ревизия 1. При победе S сверяются ID его плана, ненулевого снимка, квитанции и ответа повтора. При победе ручного создания S отсутствует.

## Истечение срока, чтение и очистка

Тесты удерживают владельца за блокировкой до перехода реальных часов PostgreSQL через срок. Для живого принятого плана повтор возвращает прежний ID при заполненном лимите и после очистки. При полном лимите настоящий PUT меняет название, добавляет ручной блок с заметкой и сметой 450 RUB. После него POST с прежним талоном и другим названием возвращает 200 с прежним ID. GET сохраняет ревизию 2, отредактированное содержимое и подытог 450,00 RUB. Байты исторического ответа совпадают с полученными до правки. Неиспользованный выбор после срока отклоняется. При удалении плана квитанция мешает его восстановлению до срока. После удаления истёкшей квитанции повтор отклоняется по времени.

Первая успешная запись очищает не более 100 истёкших квитанций. Проверка срока и очистка используют `clock_timestamp()`. Исторический GET проверяет владельца и размер UTF-8 в SQL. Хранилище принимает ровно 65 536 байт и отличает отсутствующий/чужой ID, NULL ручного плана, пустой повреждённый конверт и многобайтовое значение за пределом. Общая готовность проверяет столбец исторического снимка, ключ квитанции и индекс срока даже при выключенной записи.

В итоговом прогоне прошли все 11 случаев `SavedOptionPersistenceTests`, включая пять HTTP-гонок. Отдельно прошёл прежний `TripHotelLinkPersistenceTests.Optional_migration_preserves_plan_and_flight_link_and_requires_its_own_valid_schema`. EF CLI подтвердил соответствие актуальной модели снимку миграции.
