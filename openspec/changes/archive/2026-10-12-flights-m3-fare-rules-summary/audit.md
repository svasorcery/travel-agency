## Исходная точка и разрешения

Свежий `git fetch origin dev` вернул `163e3d9b467259518a11e6c6c423aa0e3f79a513`; `FETCH_HEAD` и `origin/dev` совпали. Проверка ancestry указанного checkpoint прошла; основной checkout был чистым. Managed worktree `flights-m3-fare-rules-plan/travel-agency` создана именно от этого SHA, с detached HEAD; старые ветки/worktrees не использовались.

Новая worktree не содержала ignored runtime OpenSpec. После отдельного ответа пользователя «Да» скопирована существующая установка из основной dev. Launcher подтвердил 1.14.0 и manifest runtimeDigest `d8c98d3e37285006042a99745ed1eaffdf1c66a7cba70a178d45ea1480d61b00`. Source tooling, lock-file, manifest, skills и config не изменялись; init/update не запускались. Sandbox требовал обычную эскалацию для fetch, копирования и дочернего Node-процесса; автоматическая проверка разрешила их.

Прочитаны root, Flights, Travel.AI и Shared AGENTS; иных AGENTS в затрагиваемом web/TS/tests нет. Прочитаны current-state, концепция 2026-05-03, применимые ADR 0006/0011/0012/0013/0020/0023/0024/0025, все четыре действующих OpenSpec contracts и дизайн SSE-архива. Историческая концепция описывает будущий MAF; принятый ADR 0012 и нынешний код устанавливают direct Anthropic/IChatClient. PR42/43 и номера CI из запроса — исходный handoff пользователя; в этой ревизии их удалённый статус отдельно не перепроверялся.

## Что подтверждает документация поставщика

Прочитаны 2026-10-12 только публичные официальные страницы; вызовов API и supplier credentials не было.

- [Guide: offer/order conditions](https://duffel.com/docs/guides/displaying-offer-and-order-conditions): root condition относится ко всем slices и пассажирам, slice change — к одному slice и всем пассажирам. Null означает неизвестность; unknown fee не означает бесплатность. Область — добровольные действия до вылета; partial refund не выводится из slice change.
- [Offers v2](https://duffel.com/docs/api/v2/offers): offer может измениться при обычном refresh; есть offer expiry, structured conditions, brand, baggage и segment-passenger fare basis. Penalty currency может отличаться от цены предложения. Это источник полей, а не обещание их наличия в каждом ответе.
- [Fare basis announcement](https://changelog.duffel.com/announcements/1-90a73325-0915-474b-97a7-423d65e19d19): поле кода располагается на segment-passenger уровне. Исторический список поддерживаемых авиакомпаний не считается текущей гарантией покрытия.

| Данные | В wire-модели проекта сейчас | Решение для объяснения |
|---|---|---|
| До-вылетное разрешение root | Два bool с потерей unknown | Nullable wire -> три состояния с source scope |
| Сбор и валюта | Отсутствуют | Добавить точное decimal-string money; missing/malformed остаётся unknown |
| Slice change | Отсутствует | Добавить; не заменяет root и не обещает partial refund |
| До/после вылета, no-show | До-вылетные field names; подробностей нет | До вылета — ограниченный scope; после/no-show — unknown |
| Сроки | ExpiresAt, itinerary; есть и payment requirements | Expiry предложения не срок возврата; payment deadline не fare-rule deadline |
| Полный текст правил | В изученном offer-контракте и текущем коде источник не установлен | Явно «полный текст не предоставлен»; без scraping/RAG, поиска правил по бренду/коду или чтения conditions-of-carriage URL как fare rules |
| Бренд, настоящий код, багаж | Частично и с потерей scope | Раздельные поля; per-leg/per-adult/per-segment; отсутствующее не дорисовывается |

## Travel.AI: факты и ограничения

[Program](../../../../apps/Travel.AI/Program.cs) использует AnthropicClient.AsIChatClient напрямую; пакеты Anthropic12.20.0 и Microsoft.Extensions.AI10.5.2 pinned в [Directory.Packages.props](../../../../Directory.Packages.props). [Extractor](../../../../apps/Travel.AI/NlSearch/NlSearchExtractor.cs) делает structured JSON extraction, но не задаёт MaxOutputTokens. [Handler](../../../../apps/Travel.AI/NlSearch/NlSearchAiHandler.cs) считает стоимость после успешного extraction по hardcoded ценам; это не предварительный budget guard. Невалидный output/исключение до extraction может не попасть в ledger. Не надо копировать включение исходного query в exception в новый summary.

[Ledger](../../../../apps/Travel.AI/Persistence/AiDbContext.cs) имеет уникальность `(MessageIdentity, CorrelationId)` после вызова; она не предотвращает повторный model call. [ADR0020](../../../../docs/adr/0020-nl-search-cross-service-contract.md) задаёт отдельные versioned leaf contracts и Core NATS request/reply с queue group; JetStream не нужен для ответа, который ценен только в текущем quote. [Официальный C# SDK](https://github.com/anthropics/anthropic-sdk-csharp/blob/main/src/Anthropic/AnthropicClient.cs) имеет retry loop; установленная XML-документация12.20.0 подтверждает ClientOptions.MaxRetries. Новый bounded client должен отключить retries, сохранив NL-search composition без изменения.
