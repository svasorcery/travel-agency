# Manual measured Rail profile

`node tools/rail/run-measured.mjs --describe` only reads and hashes the reviewed profile. It starts no fixture/process/DB/network. A source-only compile is `dotnet build tools/rail/Travel.Rail.Fixture/Travel.Rail.Fixture.csproj --configuration Release`. Build/describe are source preparation, not a measured attempt.

Only after separate explicit authorization for BOTH actual disposable Host/DB/schema fixture and measured load/memory, invoke `node tools/rail/run-measured.mjs --run-authorized --actual-host-db-authorized --receipt-dir <new-absolute-directory-under-TestResults>`. The two flags are invocation guards, not a substitute for the human authorization. The launcher performs a fresh Release build before execution, verifies the sorted source manifest is unchanged across build/run, and records the executed Host/Rail/fixture DLL hashes. It refuses receipt directories outside the repository's TestResults tree and existing attempt paths. No ordinary test carries Fact/Theory for this profile; no CI job executes it automatically.

The non-Fact `RailMeasuredProfile` reuses the existing public `HotelsHostFixture` solely for real Program.cs/disposable PostgreSQL lifecycle/isolation. It invokes real Rail HTTP routing/coordinators/production catalogue/search parsers with one terminal authored wire. All external transport methods/hosts are refused. It does not inherit any Hotels acceptance or waiver.

Same warm business state is checked before baseline and after each recovery: one Rail bundle, zero Rail search entries/loaders/active children, both search permits free. The fixture inspects private retained counters from the exact reviewed source (failure on binding drift), never adds test-only production hooks. Catalogue is generated incrementally, includes RF/non-RF branches and100000RF stations; no40MiB raw fixture file is retained. Three cycles at1and2admitted profiles each execute1000useful uncached HTTP searches, then clear search cache and wait120s in the same state. Five baseline samples span30s, median is declared before execution; no forced GC. p50/p95, attempts/useful/failures/refusals/cancellations, peak/recovered working set, quota dispatch count and128entry pressure are separate. Saturation holds four source children after two callers cancel and expects two capacity refusals; it never contributes to useful successes.

Receipts write baseline, each profile/cycle, and verdict into a NEW directory; existing attempts cannot be overwritten. Every interrupted cycle writes its partial denominator in finally, including attempted/completed/useful/failed/cancelled/in-flight calls, latency samples, phase, and dispatch deltas. Startup/failure/cancellation retain an attempt verdict and launcher log. Peak working set explicitly has process-lifetime scope, including cold catalogue and preceding cycles. A failed threshold remains RED with the original denominator/profile hash. No retry/threshold adjustment occurs. Bind the eventual run to base/head/source manifest/run/attempt separately. This harness is authored and build checked only until execution is separately authorized; it is not current Host/OpenAPI or memory/performance proof.
