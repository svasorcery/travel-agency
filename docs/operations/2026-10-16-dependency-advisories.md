## Locally patched: braces 3.0.3

[GHSA-vfj7-8cjw-p6xm / CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) affects braces <=3.0.3 and reports **no patched version**. Registry metadata on this date confirms braces 3.0.3, micromatch 4.0.8 and fast-glob 3.3.3 remain current, and OpenSpec 1.14.2 still depends on the same fast-glob line. A maintained compatible upstream update therefore does not remove this leaf. Downgrading OpenSpec to audit's suggested 0.17.2 would break the exact 1.14.0 provenance/workflow contract and is not an accepted fix.

The root chains include `vite-plugin-static-copy -> fast-glob -> micromatch -> braces`, build/dev-server `http-proxy-middleware -> micromatch`, and developer CLI/watch tooling (Spartan/ts-morph and Commitizen/chokidar/findup-sync). The API-client copy target is the static `README.md` path; reviewed build/watch patterns are repository/developer input, not a demonstrated public API input. An untrusted checkout, config or glob supplied to these tools remains relevant DoS input. Runtime reachability is not inferred from an npm dependencies/devDependencies label.

The separate tool chain is exactly `@fission-ai/openspec 1.14.0 -> fast-glob 3.3.3 -> micromatch 4.0.8 -> braces 3.0.3`. The launcher rejects braces in command identifiers and restricts schema arguments to spec-driven. Built-in generates patterns are static (including specs/**/*.md). This does **not** make the vulnerable path generally unreachable: the pinned resolver checks project-local `openspec/schemas/<name>/schema.yaml` before package schemas, including a project-local spec-driven shadow. Change metadata/project config also select schemas. Its `generates` relative-path validation rejects traversal/NUL, but does not limit brace depth. `fg.generateTasks(generates)` runs before filesystem task-base guards; those are path guards, not a brace recursion fix. A custom schema or untrusted checkout can therefore expose this local tooling DoS. No malicious payload was executed to make this assessment.

OpenSpec remains pinned to 1.14.0 with unchanged package integrity, source commit and skill/capability hashes. Its installed dependency runtime digest is updated for the backport. Both locks use one exact reviewed local security tarball for braces; all other fetched tarballs remain on HTTPS registry.npmjs.org with integrity. The strict gate verifies original provenance, patched archive/source and every installed copy. Raw version findings are accepted as locally remediated only after that proof and complete known-leaf closure; all new advisories and drift fail closed. The previous 30-day waiver was removed. See the [backport notes](2026-10-16-braces-security-backport.md) for ordinary boundary/API evidence, remaining limits and reproducible installation.

A fresh full-solution NuGet report after restoring all 53 projects found no vulnerable direct or transitive packages. This includes the AppHost/test chain absent from the earlier Host/AI-only audit.
