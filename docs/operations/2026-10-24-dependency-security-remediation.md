## Behavioural and compatibility evidence

The existing dependency-consumer command retains its seven cases and adds eight focused cases. On the original dependencies, three new regressions failed for the intended reason: the copy consumer emitted a trailing script-close prefix, Ajv's URI dependency decoded an encoded scheme into a trusted scheme, and Angular builder's undici terminated an isolated child with an unhandled response-length mismatch after rejecting excessive content encodings. All three pass after the updates.

Both retained Express variants pass valid gzip JSON → malformed gzip refusal → valid request recovery. This is compatibility coverage, not a reproduction of the trailing-bytes body-parser crash. No large-resource or public-endpoint probe was used. Undici uses a loopback server, a two-request sequence, a128MiB child heap and explicit deadlines; the disposable child protects the test runner from the old uncaught error. The serialisation test inspects strings without rendering or evaluating the supplied function text.

Spartan tests exercise its real exported Angular/Nx config schemas, defaults, custom aliases, invalid field paths and readable diagnostics; its real CSS style-record parser rejects invalid keys/values. The actual UI button generator runs against an Nx virtual tree, emits styled TypeScript and path mappings, and does not execute its returned dependency-install task. This covers both Zod use sites found in the retained CLI; it does not claim exhaustive coverage of every generator or identical error-message formatting across Zod majors. Nx's existing /virtual workspace diagnostic occurs on both baseline and candidate and does not represent an on-disk project mutation.
