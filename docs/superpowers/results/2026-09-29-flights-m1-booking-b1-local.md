# Flights M1 B1: локальная проверка анонимного quote frontend

**Дата:** 2026-09-29. **База:** свежий `origin/dev` `1ce3004f82e38de0512542260cd347a2bad6956e`; отдельная ветка `codex/flights-m1-booking-design` создана ровно от этого SHA. **Граница отчёта:** локальная проверка B1 до commit/CI/merge, без миграций и деплоя. Публикация и удалённый CI подтверждаются отдельно. B2/B3 не начаты.

## Реализованная граница

- Bookable карточка вызывает анонимный quote; partner не получает booking action. Первый quote сравнивается с исходным поиском даже при `priceChanged=false` backend. В панели рядом видны цена поиска и цена после проверки; повторный quote также показывает цену предыдущей проверки. Изменение цены, маршрута или показанной длительности требует явного принятия; re-quote использует тот же aggregateId и ref.
- Quote HTTP response теперь отдаёт `FareConditionsDto` из уже существующего `BookableOffer.FareConditions`; БД и домен не менялись. UI показывает возможность изменения/возврата без обещания бесплатной услуги. Багаж обозначен как максимум отдельного сегмента, поскольку mapper не отдаёт точную норму по каждому участку.
- В изолированном demo ref детерминированно содержит тип поездки и даты, а aggregate ID привязан к полному ref. Это устраняет неоднозначность старого одинакового fake ref и запрещает re-quote с ID другого маршрута без server-side состояния последнего поиска. Фиктивные fetchedAt/expiry упорядочены и предшествуют вылету; срок и цена явно помечены вымышленными.
- Quote errors/timeout/malformed response, expiry, ручной retry и очистка при изменении поиска проверены. Потерянный HTTP ответ не объявляется успехом и не вызывает автоматический повтор, поскольку quote не имеет idempotency key.
- Quote panel вынесен в один presentation component после предупреждения production style budget. Состояние и HTTP остались в существующей странице; новый store или UI framework не добавлен.

В .NET test build появляется warning `AD0001` из `Microsoft.AspNetCore.Analyzers.RouteHandlers.RouteHandlerAnalyzer`; тесты завершились успешно. Локальный `npm ci` сообщил engine warning для системного Node 22.18; frontend gate запускался на bundled Node 24.19.

Независимое read-only ревью нашло шесть проблем: завышенное обещание багажа, пустой GUID, несверенный aggregate при re-quote, неверную подпись retry, запаздывание expiry и переиспользование demo aggregate между датами. Каждая исправлена после воспроизводящего RED-теста; финальные затронутые наборы повторно прошли. Демо-срок вычисляется из даты вылета для детерминированности, **не моделирует реальный короткий TTL поставщика**.

Дополнительное саморевью нашло, что экран не показывал старую и новую цену рядом, игнорировал изменение длительности без смены сегмента и называл 409 неизвестным исходом. Сообщение об ошибке повторного quote также обещало новую проверку при повторе старого aggregate. При изменении маршрута старую и новую карточки теперь видно в одной панели до принятия. Копия для 409 нейтральна: backend возвращает этот статус как при конкурентном конфликте, так и при недопустимом состоянии. Эти случаи исправлены после RED-тестов; browser smoke проверил сравнение цен и отсутствие горизонтального скролла на 360px.

## Предел доказательства и следующий gate

Браузерное демо использует только Node stub. No-DB HTTP test проверяет реальную сериализацию endpoint с fake bus, но не полный Host/Wolverine/Marten/поставщика. Не вызывались Duffel, Travelpayouts, Anthropic, платёж, Keycloak или реальная БД; миграции не применялись. `Confirmed`, `Ticketed` и заказ здесь отсутствуют по границе B1.

После review B1 следующий инкремент B2 — локальный auth-контракт Keycloak, возврат к re-quote, данные одного пассажира, hold/confirm и отдельные проверки идемпотентности. Контрактные решения и запрет на скрытую имитацию настоящего JWT описаны в спецификации.
