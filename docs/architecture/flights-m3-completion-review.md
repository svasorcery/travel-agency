# Ревизия завершения Flights M3

Дата: 2026-10-12. Проверенная исходная точка — свежий `origin/dev` / `321159929e78c20049b49619895128c663f17d16`. Новая managed worktree создана от этой точки; ancestry проверена до создания `codex/flights-m3-closeout`. Проверка ограничена исходниками, контрактами и существующими CI receipts. Локальные Host/AppHost/Travel.AI/DB, ключи, миграции и внешние API не запускались.

## Вывод и границы завершения

Все продуктовые пункты [M3 roadmap](../superpowers/specs/2026-05-03-travel-platform-concept.md) имеют реализованный source-срез и принятие в CI: места, дополнительный багаж, отмена и клиентский возврат, объяснение тарифа, обновление статуса заказа. Пять действующих [OpenSpec contracts](../../openspec/specs/) синхронизированы, завершённые changes архивированы. В каждом срезе сохранены собственные границы доказательств.

**Source-часть M3 готова для перехода к проектированию Support.** Это не принятие работающего окружения и не подтверждение качества включённого AI. Структурированное объяснение тарифа доступно независимо от модели; AI-кандидат выключен по умолчанию, его польза ещё не измерена. Клиентский возврат реализован через TestOnly gateway для тестового кошелька; зачисление реальных денег и Production PSP не подтверждены. Эти ограничения следуют из принятых контрактов, а не снимаются завершением roadmap.

## Что остаётся отдельно

1. **AI D7.** [Фиксированный evaluation packet](../../tests/Travel.Tests.AiEvals/Flights/FareSummary/README.md) содержит 48 cases, 16 holdout: 12 заранее eligible и 4 ожидаемых отказа. Модель/цена не выбраны, paid run не выполнен. Нужны отдельно разрешённые exact model/pricing, реальные usage/cost, whole optional-stage latency и слепое сравнение двух русскоязычных читателей. Чистый extractor runner один не проходит весь gate. При провале остаётся baseline и выключенный AI.
2. **Работающее окружение.** Нужны отдельно согласованные consumer-before-producer/совместимость browser assets, stream proxy и восстановление подключения. Проверка deployment не разрешает финансовую операцию. Single-process SSE не становится multi-node гарантией.
3. **Поставщик и деньги.** Duffel API — реальная интеграция, но sandbox ещё не проверен этим набором доказательств. Test wallet/refund gateway не отправляют реальные деньги. [ADR0019](../adr/0019-payment-gateway-abstraction.md) и customer-refund contract требуют отдельного решения и разрешения для PSP/settlement/bank-credit acceptance.
4. **Отложенный продуктовый scope.** Частичные/сервисные refunds, post-booking ancillaries, after-departure/no-show/involuntary policies не реализуются из fare flags. Roadmap Tier3 и каждый capability contract сохраняют эти ограничения; они не включаются скрытно в закрытие M3.

## Следующий шаг: Support / Laya

Ревизия не обнаружила отсутствующего source-среза в согласованной демонстрационной области M3. Следующий цикл — отдельное проектирование Support по [roadmap 1a](../superpowers/specs/2026-05-03-travel-platform-concept.md): S1 — один входящий канал, owner-bound order link, очередь оператора, статусы и ответ; затем S2 — классификация Laya с manual fallback; S3 — размеченная RU/EN выборка, baseline, holdout, shadow comparison и численные критерии включения.

Support не отменяет заказ и не отправляет деньги. Срочность определяется явными правилами по подтверждённому состоянию/времени до вылета; клиентский текст не доказывает финансовое состояние. Границы нового модуля, published Flights contract, PII retention, размещение Laya и критерии качества ещё требуют отдельной спецификации. Этот отчёт не является её заменой и не разрешает новую реализацию или внешний rollout.
